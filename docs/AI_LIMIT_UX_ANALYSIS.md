# 🎯 Анализ UX для счетчика AI запросов

## 📊 Два варианта

### Вариант 1: Скрыть счетчик, показывать только предупреждение

**Плюсы:**
- ✅ Проще UX - не отвлекает пользователя
- ✅ Меньше визуального шума
- ✅ Пользователь не думает о лимитах постоянно
- ✅ Проще реализация

**Минусы:**
- ❌ Пользователь не знает, сколько осталось
- ❌ Может расстроиться, когда внезапно увидит лимит
- ❌ Не может планировать использование

---

### Вариант 2: Счетчик в реальном времени

**Плюсы:**
- ✅ Прозрачность - пользователь видит свой лимит
- ✅ Может планировать использование
- ✅ Видит, когда приближается к лимиту

**Минусы:**
- ❌ Нужно обновлять после каждого запроса
- ❌ Больше сложности в реализации
- ❌ Больше запросов к API
- ❌ Может создавать стресс ("осталось только 3 запроса!")

---

## 💡 Рекомендуемый подход: Гибридный

### Стратегия:

1. **Скрыть счетчик по умолчанию**
   - Не показывать постоянно
   - Не создавать стресс

2. **Показывать предупреждения:**
   - Когда осталось 1-2 запроса → предупреждение
   - Когда лимит достигнут → блокировка с предложением апгрейда

3. **Детальная информация в профиле:**
   - Показывать полную статистику AI использования
   - История использования
   - План и лимиты

4. **На странице Chat - опциональный счетчик:**
   - Можно показать маленький счетчик
   - Но не навязчиво

---

## 🎨 Конкретная реализация

### Где показывать:

1. **Страница Chat (`/chat`):**
   - ✅ Маленький счетчик в header (как сейчас)
   - ✅ Предупреждение при достижении лимита

2. **Другие страницы (Wheel, Analytics, Goals):**
   - ❌ Без счетчика
   - ✅ Предупреждение при попытке использовать AI и достижении лимита

3. **Страница Profile (`/profile`):**
   - ✅ Детальная информация о лимитах
   - ✅ Статистика использования

4. **Предупреждения:**
   - Осталось 1-2 запроса → toast/уведомление
   - Лимит достигнут → модальное окно с апгрейдом

---

## ✅ Рекомендация: Вариант 1 (Скрыть + предупреждения)

**Почему:**

1. **Лучше UX:**
   - Не создает стресс
   - Пользователь не думает о лимитах постоянно
   - Предупреждения работают лучше, чем постоянный счетчик

2. **Проще реализация:**
   - Не нужно обновлять счетчик в реальном времени
   - Меньше запросов к API
   - Меньше сложности

3. **Эффективнее:**
   - Предупреждения работают так же хорошо
   - Пользователь все равно узнает о лимите
