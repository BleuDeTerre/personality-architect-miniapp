# План оптимизации производительности приложения

## 📋 Обзор

Этот документ описывает 7 ключевых оптимизаций для ускорения загрузки приложения, разделов, изображений и страниц.

---

## ✅ 1. Service Worker - кэширование ресурсов

### Проблема
Service Worker сейчас используется только для push-уведомлений и не кэширует статические ресурсы и API запросы.

### Решение
Добавить полноценное кэширование:
- **Статические ресурсы** (JS, CSS, изображения, шрифты) - кэш навсегда с версионированием
- **API запросы** - стратегия `stale-while-revalidate` для быстрого ответа
- **HTML страницы** - кэш с проверкой обновлений

### Ожидаемый эффект
- Повторные загрузки страниц: **в 5-10 раз быстрее**
- Офлайн-работа: базовые функции доступны без интернета
- Снижение нагрузки на сервер: **30-50% меньше запросов**

### Реализация
- Обновить `public/sw.js` с обработчиками `fetch`
- Добавить стратегии кэширования для разных типов ресурсов
- Версионирование кэша для обновлений

## ✅ 2. Оптимизация изображений (BadgeImage)

### Проблема
Компонент `BadgeImage` использует `unoptimized={true}`, что отключает оптимизацию Next.js (AVIF/WebP конвертацию, ресайзинг).

### Решение
- Убрать флаг `unoptimized` из `BadgeImage`
- Добавить `priority={false}` для lazy loading бейджей ниже fold
- Использовать `loading="lazy"` для изображений вне viewport

### Ожидаемый эффект
- Размер изображений: **на 50-70% меньше** (WebP/AVIF вместо PNG)
- Загрузка бейджей: **в 2-3 раза быстрее**
- LCP улучшение: **на 0.5-1 секунду**

### Реализация
- Обновить `src/components/BadgeImage.tsx`
- Убрать `unoptimized`, добавить `loading="lazy"` где нужно

## ✅ 3. Оптимизация шрифтов

### Проблема
Material Symbols загружается через внешний CSS (`fonts.googleapis.com`), что блокирует рендеринг и добавляет задержку.

### Решение
- Self-host Material Symbols шрифт (скачать и разместить в `public/fonts/`)
- Использовать `next/font/local` для оптимизации
- Или использовать иконки из `lucide-react` вместо Material Symbols

### Ожидаемый эффект
- Устранение блокировки рендеринга: **FCP улучшение на 0.3-0.5с**
- Снижение зависимостей от внешних ресурсов
- Улучшение производительности на медленных соединениях

### Реализация
- Вариант 1: Self-host Material Symbols
- Вариант 2: Заменить на `lucide-react` (уже в зависимостях)
- Обновить `src/app/layout.tsx`

## ✅ 4. Добавление Cache-Control заголовков для API

### Проблема
Не все API роуты используют оптимальные Cache-Control заголовки, что приводит к лишним запросам.

### Решение
Добавить Cache-Control заголовки для всех API роутов:
- **Публичные данные** (лидерборд, квесты) - `public, s-maxage=300, stale-while-revalidate=600`
- **Персональные данные** (привычки, цели) - `private, max-age=300, stale-while-revalidate=600`
- **Динамические данные** (чат, AI) - `no-cache` или короткий TTL

### Ожидаемый эффект
- Повторные запросы: **в 10-50 раз быстрее** (из кэша)
- Снижение нагрузки на БД: **40-60% меньше запросов**
- Улучшение UX: мгновенные ответы для кэшированных данных

### Реализация
- Использовать `getCacheHeaders` из `src/lib/serverCache.ts`
- Добавить заголовки во все API роуты
- Проверить роуты без кэширования

## ✅ 5. Оптимизация загрузки данных на страницах

### Проблема
На некоторых страницах данные загружаются последовательно вместо параллельно.

### Решение
- Использовать `Promise.all` для параллельной загрузки независимых данных
- Оптимизировать запросы на страницах: `/habits`, `/goals`, `/wheel`, `/analytics`
- Добавить loading states для лучшего UX

### Ожидаемый эффект
- Время загрузки страниц: **на 30-50% быстрее**
- Улучшение TTI (Time to Interactive)
- Лучший UX с прогресс-индикаторами

### Реализация
- Проверить все страницы на последовательные запросы
- Заменить на `Promise.all` где возможно
- Добавить оптимистичные обновления UI

## ✅ 6. Оптимизация bundle size

### Проблема
Возможно, в bundle попадают неиспользуемые зависимости, что увеличивает размер.

### Решение
- Проверить размер bundle через `next build --analyze`
- Оптимизировать импорты (использовать named imports вместо default)
- Использовать dynamic imports для тяжелых библиотек
- Проверить дублирование зависимостей

### Ожидаемый эффект
- Размер bundle: **на 20-30% меньше**
- Ускорение первой загрузки: **на 0.5-1 секунду**
- Улучшение FCP и LCP

### Реализация
- Добавить `@next/bundle-analyzer` для анализа
- Оптимизировать импорты в компонентах
- Использовать `dynamic()` для тяжелых библиотек

## ✅ 7. Оптимизация рендеринга

### Проблема
Возможны лишние ре-рендеры компонентов, что замедляет UI.

### Решение
- Добавить `React.memo` для компонентов, которые редко меняются
- Использовать `useMemo` для тяжелых вычислений
- Использовать `useCallback` для функций, передаваемых в дочерние компоненты
- Оптимизировать состояние (разделить на мелкие части)

### Ожидаемый эффект
- Плавность UI: **на 30-40% лучше**
- Снижение нагрузки на CPU: **на 20-30%**
- Улучшение FPS при скролле и взаимодействии

### Реализация
- Найти компоненты с частыми ре-рендерами
- Добавить мемоизацию где нужно
- Использовать React DevTools Profiler для анализа
