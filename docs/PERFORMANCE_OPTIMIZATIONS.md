# Оптимизации производительности

## Выполненные оптимизации

### 1. Next.js конфигурация ✅
- Включена gzip компрессия
- Оптимизация изображений (AVIF, WebP) - **только для next/image компонента**
- Оптимизация импортов пакетов
- Минификация через SWC

**ВАЖНО**: Настройки изображений НЕ влияют на:
- API роуты (`/api/share/preview`, `/api/share/og`) - касты работают как прежде
- Статические изображения с флагом `unoptimized` (например, `BadgeImage`)
- Любые другие изображения, не использующие компонент `next/image`

### 2. Оптимизация задержек ✅
- **Задержка `setTimeout(100)` сохранена** на главной странице - она нужна для корректного восстановления сессии Supabase
- Убраны debounce задержки в `AIMotivationMessage` (React 19 не дублирует эффекты в Strict Mode)

### 3. Prefetching ✅
- Добавлен `prefetch={true}` для всех навигационных ссылок на главной странице
- Это предзагружает страницы при наведении курсора

### 4. React.memo ✅
- `DailyWellness` - мемоизирован для предотвращения лишних перерендеров
- `AIMotivationMessage` - мемоизирован
- `TodaysOverview` - мемоизирован

### 5. Оптимизация useEffect ✅
- Объединены два `useEffect` в `DailyWellness` в один
- Убраны дублирующиеся вызовы функций

### 6. Preconnect для внешних ресурсов ✅
- Добавлены preconnect для Google Fonts
- Добавлен dns-prefetch для Neynar API и Supabase

## Дополнительные рекомендации

### 1. Service Worker и кеширование
Приложение уже использует Service Worker через `ServiceWorkerRegistration`. Убедитесь, что:
- Кешируются статические ресурсы
- API запросы кешируются с правильными TTL
- Используется stale-while-revalidate стратегия

### 2. Оптимизация изображений
- Используйте Next.js Image компонент для всех изображений
- Убедитесь, что изображения оптимизированы (WebP/AVIF)
- Используйте lazy loading для изображений ниже fold

### 3. Code Splitting
- Уже используется `dynamic()` для ленивой загрузки компонентов
- Рассмотрите разделение больших страниц на более мелкие chunks

### 4. Database оптимизации
- Убедитесь, что есть индексы на часто используемые поля
- Используйте `select()` только для нужных полей
- Рассмотрите использование материализованных представлений для сложных запросов

### 5. API оптимизации
- Запросы уже батчатся через `Promise.all`
- Используется кеширование на клиенте и сервере
- Рассмотрите GraphQL для более эффективных запросов

### 6. Мониторинг производительности
- Используйте Lighthouse для проверки производительности
- Отслеживайте Core Web Vitals (LCP, FID, CLS)
- Мониторьте время ответа API

## Метрики для отслеживания

1. **First Contentful Paint (FCP)** - должен быть < 1.8s
2. **Largest Contentful Paint (LCP)** - должен быть < 2.5s
3. **Time to Interactive (TTI)** - должен быть < 3.8s
4. **Total Blocking Time (TBT)** - должен быть < 200ms
5. **Cumulative Layout Shift (CLS)** - должен быть < 0.1

## Проверка оптимизаций

Запустите Lighthouse в Chrome DevTools:
```bash
# В браузере откройте DevTools -> Lighthouse
# Выберите "Performance" и запустите аудит
```

Или через CLI:
```bash
npm install -g lighthouse
lighthouse https://your-app-url.com --view
```
