# Процесс аутентификации в Personality Architect

## Текущая реализация (автоматическая аутентификация)

### Как это работает:

1. **Получение FID через Farcaster SDK**
   - При загрузке страницы вызывается `getUserFid()` из `@/lib/farcaster-sdk`
   - Эта функция использует `getFrameContext()`, который вызывает `sdk.context?.getFrameContext?.()`
   - Farcaster Mini App SDK автоматически предоставляет контекст пользователя, включая его FID (Farcaster ID)

2. **Проверка существующей сессии**
   - Проверяется, есть ли активная сессия в Supabase: `supabase.auth.getUser()`
   - Если сессия есть → пользователь уже авторизован, ничего делать не нужно

3. **Автоматический логин (если сессии нет)**
   - Если сессии нет, отправляется POST запрос на `/api/auth/farcaster-login` с FID
   - На сервере происходит:
     a. Поиск пользователя по FID в таблице `users`
     b. Если пользователя нет → создается новый пользователь в Supabase Auth и в таблице `users`
     c. Если пользователь есть → обновляется его метаданные
     d. Получение профиля из Neynar (если доступно) и сохранение в `farcaster_profiles`
     e. Генерация access_token для Supabase сессии
   - Возвращается `access_token`, который устанавливается в сессию: `supabase.auth.setSession({ access_token, refresh_token: '' })`

### Преимущества текущего подхода:

✅ **Без паролей** - пользователь не вводит никаких данных  
✅ **Без форм** - все происходит автоматически  
✅ **Без кнопок "Войти"** - аутентификация прозрачна для пользователя  
✅ **Безопасно** - FID предоставляется напрямую от Farcaster SDK, подделать невозможно  
✅ **Быстро** - один запрос к API и пользователь авторизован  

### Пример кода (из `src/app/page.tsx`):

```typescript
useEffect(() => {
  (async () => {
    // 1. Получаем FID из Farcaster SDK
    const fid = await getUserFid();
    if (!fid) return;

    // 2. Проверяем, есть ли сессия
    const { data } = await supabase.auth.getUser();
    if (!data.user) {
      // 3. Если нет сессии - автоматически логинимся
      const res = await fetch('/api/auth/farcaster-login', {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({ fid }),
      });
      const { access_token } = await res.json();
      if (access_token) {
        // 4. Устанавливаем сессию
        await supabase.auth.setSession({ access_token, refresh_token: '' });
      }
    }
  })();
}, []);
```

### Что происходит на сервере (`/api/auth/farcaster-login`):

1. **Валидация FID** - проверка, что FID валидный (число от 1 до 2,147,483,647)
2. **Поиск пользователя** - поиск в таблице `users` по FID
3. **Создание/обновление пользователя**:
   - Если пользователя нет → создается через `admin.auth.admin.createUser()`
   - Если есть → обновляются метаданные через `admin.auth.admin.updateUserById()`
4. **Получение профиля Neynar** (опционально):
   - Запрос к Neynar API для получения полного профиля
   - Сохранение в таблицу `farcaster_profiles`
5. **Генерация токена** - создание access_token для Supabase сессии
6. **Возврат токена** - отправка `access_token` клиенту

### Почему не используется `sdk.actions.signIn()`?

`sdk.actions.signIn()` - это метод для **явной** аутентификации, когда нужно показать пользователю кнопку "Войти" или форму. 

В нашем случае:
- Пользователь уже авторизован в Farcaster (иначе он не смог бы открыть Mini App)
- FID доступен автоматически через `getFrameContext()`
- Нет необходимости в дополнительных действиях от пользователя

**Текущий подход лучше**, потому что:
- Пользователь не видит никаких форм или кнопок
- Аутентификация происходит мгновенно
- Меньше шагов для пользователя

### Когда может понадобиться `sdk.actions.signIn()`?

Только если:
- Нужна явная кнопка "Войти" для UX
- Нужно показать пользователю процесс авторизации
- Требуется дополнительная валидация перед входом

В нашем случае это не нужно, так как пользователь уже в Farcaster и мы просто получаем его FID.

## Схема потока:

```
[Пользователь открывает Mini App]
         ↓
[Farcaster SDK автоматически предоставляет контекст]
         ↓
[getUserFid() получает FID из SDK]
         ↓
[Проверка: есть ли сессия Supabase?]
         ↓
    [НЕТ] → [POST /api/auth/farcaster-login с FID]
         ↓
    [Создание/обновление пользователя в Supabase]
         ↓
    [Получение access_token]
         ↓
    [Установка сессии в Supabase]
         ↓
[Пользователь авторизован ✅]
```

## Безопасность:

- ✅ FID валидируется на сервере
- ✅ Опциональный `FAR_LOGIN_SERVER_SECRET` для дополнительной защиты
- ✅ FID предоставляется напрямую от Farcaster SDK (нельзя подделать)
- ✅ Все операции на сервере используют Service Role ключ (безопасно)
